# Run locally

You need Python 3.10+ and Node.js 18+ installed.

## 1. Start the backend

Open a terminal in the project folder:

```powershell
cd backend
python -m venv .venv
```

Activate the environment on Windows with `.venv\Scripts\Activate.ps1`, or on macOS/Linux with `source .venv/bin/activate`. Then install and run:

```powershell
pip install -r requirements.txt
uvicorn app.main:app --reload
```

The API is at `http://localhost:8000`; interactive API docs are at `http://localhost:8000/docs`.

## 2. Start the frontend

Open a second terminal in the project folder:

```powershell
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite (usually `http://localhost:5173`). Vite forwards `/api` requests to the backend on port 8000.

Without Supabase credentials, trips are stored in `backend/database/trips.db` using SQLite. This local database persists across restarts and is ignored by Git.

The browser creates a random owner ID in `localStorage` and sends it with trip requests. Trips are listed and changed only when the same ID is provided. Clearing site storage or using another browser creates a new ID, and old trips will no longer appear in that browser. This is a demo-only separation method, not authentication.

## Optional Supabase database

1. Create a Supabase project.
2. Open its SQL Editor and run `backend/database/schema.sql`.
3. Copy `backend/.env.example` to `backend/.env` and fill in the project URL, anon key, and service role key:

```text
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
```

The app loads `backend/.env` when starting from the backend folder. The service role key is private and must only be set on the backend. Never add it to React or commit it. The service role bypasses row-level security. Browser owner IDs provide basic separation for this demo, but they can be copied or changed and are not secure authentication. Keep the demo API private until real authentication and per-user access checks are implemented. The database wrapper also exposes separate `get_client()` and `get_service_client()` methods for anon and server-side clients.

After changing an existing Supabase table, run the updated `backend/database/schema.sql` again to add the `owner_id` column, then restart the backend. Older trips receive an empty owner ID and are not visible in the app; newly created trips use the browser's owner ID.

The auth schemas do not yet implement authentication.

## Optional Groq AI

The app uses Groq for recommendations, itinerary generation, and itinerary refinements. Add your key to `backend/.env` and restart Uvicorn:

```text
GROQ_API_KEY=your-groq-key
GROQ_MODEL=openai/gpt-oss-20b
```

`GROQ_MODEL` is optional. Keep the key private and do not put it in frontend code. Without a key, the app shows starter suggestions and a basic schedule; refinement requests are saved as notes instead of being regenerated by AI.

## Run backend checks

From the project folder, install the development dependencies and run the API/SQLite checks:

```powershell
cd backend
pip install -r requirements-dev.txt
cd ..
pytest backend/tests -q
```

Run `npm ci` and `npm run build` in `frontend` if you want to check the production UI bundle.

For Render deployment, follow [DEPLOYMENT.md](DEPLOYMENT.md).
